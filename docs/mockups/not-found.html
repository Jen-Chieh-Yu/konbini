Ready · 現有的程式就做得到

  • Catch-all 路由 — 在 router/index.ts 最後加 { path: '/:pathMatch(.*)*', name: 'NotFound' }，純前端。
  • 商品不存在 — GET /api/products/{id} 找不到時回 404，ProductDetailView 依狀態碼區分「找不到」與「載入失敗」。
  • 推薦商品 — 用 GET /api/products?page=1&pageSize=5，與首頁同一支 API。
  • 部署環境 — nginx 已把未知路徑導回 index.html（SPA），404 由前端路由處理。

Blocked · 後端沒有的功能

  • 熱門或相關推薦 — 沒有銷售排行，「看看這些商品」只是第 1 頁的前幾件。
  • 回應 404 狀態碼 — SPA 對任何網址都回 200，搜尋引擎看不到 404；不正式上線，接受。

Reference

與參考網站的區塊對照

只記錄版型結構的觀察，不沿用任何網站的配色、插圖、文案與素材。

參考網站的做法Konbini調整理由
雜貨電商常見：404 頁保留完整 header、給搜尋與分類入口header 不變＋頁內搜尋＋分類膠囊迷路的人最需要的是出口；header 本來就有搜尋，頁內再放一個更顯眼的。
KALDI：找不到的商品頁仍顯示站內導覽商品 404 留在商品頁版面麵包屑與分類列還在，使用者不會以為整個網站壞了。
家樂福線上購物：錯誤頁下方推薦商品看看這些商品（5 件）讓 404 不是死路；用現有 API 就做得到。

Layout

為什麼這樣排

做法說明
「404」用等寬字、品牌色不另外畫插圖（素材要原創），用字本身當視覺重點。
404 頁只給一個主要按鈕「回首頁」是主要出口；分類與搜尋是次要出口，用膠囊與搜尋框呈現。
不存在 ≠ 載入失敗500 或網路問題說「找不到」會誤導；ui-guidelines 的錯誤狀態是「可重試」。
