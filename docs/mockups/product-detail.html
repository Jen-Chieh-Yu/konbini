Ready · 現有的 API 就做得到

  • 商品名、價格、單張圖片、商品編號 — GET /api/products/{id} 的 product（id / type / name / price / imageUrl）；價格用 formatMoney。
  • 麵包屑與分類標籤 — type 經 categoryName() 轉成「泡麵」，不需要後端回傳分類名（初版草稿時還沒有這個對照）。
  • 加入購物車 — cart.add(item, qty)；每項上限 99（MAX_ITEM_QUANTITY），數量選擇器的上限是「99 − 購物車已有的件數」。
  • 相關商品 — relevantProducts，同分類、最多 8 件；用商品卡（與列表同一個元件，不放加入按鈕）。
  • 404 與載入失敗分開處理 — API 找不到商品時回 404，見 not-found.html。

Blocked · 後端沒有的功能

  • 多張商品圖 — Product.ImageUrl 只有一張；縮圖列在只有一張圖時不顯示。
  • 原價、庫存 — 需要 ListPrice、Stock，與首頁、列表同一批欄位。
  • 產地、商品說明、規格表 — 需要 Origin、Description，以及內容量、有效期限、保存方法、過敏原等規格欄位。初版草稿建議直接加在 Product 上（固定欄位、一對一），schema 仍待決定。
  • 評價 — 需要 Review 資料表（商品、會員、星等、內容、時間、是否已購買），是這頁工程量最大的一塊，可以最後做。

Layout

為什麼這樣排

做法說明
加入購物車只在這頁列表、搜尋、首頁、404 推薦的商品卡都只連到這裡；看過價格、規格、選好數量才加入。唯一的例外是訂單列表的「再買一次」（照整筆訂單的品項與數量加入）。
數量 48px、加入按鈕 52px與表單頁同一組尺寸；el-input-number 要放大（ui-guidelines 特別點名）。
加入後不自動打開購物車顯示提示與「查看購物車」連結，要不要去購物車由使用者決定；改數量與結帳都在 /cart。
手機底部固定條改成「加入購物車」其他頁的固定條是購物車入口；說明頁的主要動作是加入，固定條跟著換，用上方數量選擇器的值。
拿掉初版的「配這個也不錯」跨分類推薦沒有 API，先只做同分類的相關商品。

Notes

下一步

  • 商品欄位（ListPrice、Stock、Description、規格）要一次補齊還是分批，等你決定；首頁、列表、說明頁都在等同一批欄位。
  • 換商品時捲回頂端：從相關商品點到另一個商品，路由參數變了但元件沒有重建，要重新載入資料並捲回頂端。
