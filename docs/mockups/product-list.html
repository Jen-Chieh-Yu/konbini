Ready · 現有的 API 就做得到

  • 分類列表與分頁 — GET /api/products?type=&page=&pageSize= 回 PagedResult（items / totalCount / page / pageSize），預設每頁 20 件。頁碼與分類放網址，重新整理與上一頁都會回到同一頁。
  • 搜尋與多關鍵字 — GET /api/search?q= 以空白分隔、每個關鍵字都要符合（ILike，不分大小寫）。關鍵字標籤的 ✕ 只是把那個字從 q 拿掉再搜一次。
  • 件數與頁數 — 由 totalCount 與 pageSize 算出，不需要新欄位。
  • 「已在購物車 × 2」角標 — 讀 Pinia 的購物車內容比對 productId，不需要 API。卡片上不放加入按鈕，加入購物車只在商品說明頁。
  • 四種狀態 — 載入中用 el-skeleton、空與錯誤用 el-empty，與 HomeView 相同寫法。

Blocked · 後端沒有的功能

  • 排序（新到貨、價格高低）— API 沒有 sort 參數，目前固定照資料庫順序。
  • 產地篩選 — 商品沒有產地欄位，「日本／韓國」只出現在商品名稱裡。要做得先加欄位，不建議用名稱比對。
  • 價格區間 — API 不支援，若要做跟排序一起加在 GET /api/products。
  • 搜尋限定分類 — /api/search 只收 q，所以搜尋結果的左欄只當「到分類逛逛」的連結，不是篩選器。
  • 庫存、原價、新品標籤 — 商品只有 Id / Type / Name / Price / ImageUrl，卡片上不畫缺貨與折扣。

Reference

與參考網站的區塊對照

只記錄版型結構與資訊密度的觀察，不沿用任何網站的配色、圖示、文案與素材；細節實作前以實際網站為準。

參考網站的做法Konbini調整理由
KALDI：列表頁左側常駐分類，右側商品格線左欄 230px 分類＋右側 4 欄與首頁 HomeView 的 el-col md=6 lg=5 左欄同寬，換頁時版面不跳動。
家樂福線上購物：列表上方顯示件數與排序標題列＝分類名＋件數＋頁數件數現在就算得出來；排序先畫位置、標為後端未支援。
Instacart：商品卡上直接加入購物車不採用：卡片只導到商品說明頁加入購物車集中在商品說明頁，看過規格與數量再加；卡片留「已在購物車 × 2」角標，掃一眼就知道哪些買過。
全聯 PXGo!：手機版以分類頁籤橫向切換手機：左欄隱藏，分類用 header 的橫向分類列手機沒有側欄空間；header 的分類列本來就能橫向捲動，目前分類有底線標示，不在列表上方再放一組。
雜貨電商常見：手機底部固定購物車入口底部固定條：件數＋合計＋看購物車ui-guidelines 的 RWD 表規定；列表頁就要看得到，不只在購物車頁。

Layout

為什麼這樣排

做法說明
分類與搜尋共用一個版面兩個 API 都回 PagedResult<ProductDto>，差別只有標題與左欄。實作抽一個列表元件（格線＋分頁＋四種狀態）給兩個 view 用——已有 2 個使用者，符合抽象門檻。
桌機 4 欄，不是 5 欄el-col 是 24 格，5 欄排不出來；4 欄（lg=6）一頁 20 件剛好 5 列。超寬螢幕（xl）可改 6 欄（xl=4）。
卡片不放加入按鈕與首頁相同，整張卡片是連到商品說明頁的連結；加入購物車只在說明頁操作，購物車的入口與規則集中在一處。卡片因此更矮，一屏看得到的品項更多。
手機 2 欄雜貨密度優先；整張卡片都是點擊範圍，遠大於 44px。
找不到時不另開頁在格線的位置顯示，搜尋框仍在 header，使用者可以直接改關鍵字。

Notes

下一步
