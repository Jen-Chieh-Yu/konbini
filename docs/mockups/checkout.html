連不到 API 時改顯示「連線失敗，購物車內容都還在，請稍後再試」。

Ready · 現有的 API 就做得到

  • 送出訂單 — POST /api/orders 收 items / contactName / contactPhone / deliveryMethod / cityCode / districtCode / streetAddress / memo，回 orderId。金額、運費由後端重新計算。
  • 縣市與行政區連動 — GET /api/addresses/cities 與 /cities/{cityCode}/districts。
  • 帶入會員資料 — GET /api/auth/me 回 name / phone；手機是選填欄位，沒填過就留空。
  • 欄位錯誤 — 後端回 errors 字典（contactName / contactPhone / streetAddress / memo / address / items），對應到欄位下方；items 與 address 沒有單一欄位，只放在 modal。長度上限：姓名 100、電話 20、地址 200、備註 500。
  • 送出後 — 清空購物車，導到下單完成頁（見 order-complete.html）。

Blocked · 後端沒有的功能

  • 超商取貨 — deliveryMethod 欄位存在，但後端沒有定義其他值，也沒有門市選擇；運費規則只有一種。
  • 配送時段 — 訂單沒有時段欄位（ui-guidelines「配送時段選擇器」）。
  • 付款 — 沒有任何付款流程；畫面寫「貨到付款」只是說明現況，若要做線上付款是一整條金流串接。
  • 常用地址 — 沒有會員地址簿，每次都要重填；要做需要新的資料表與 API。
  • 手機格式檢查 — 後端只檢查必填與長度；前端可以加 09 開頭 10 碼的格式檢查，但兩邊規則要一致。

Reference

與參考網站的區塊對照

只記錄版型結構與資訊密度的觀察，不沿用任何網站的配色、圖示、文案與素材；細節實作前以實際網站為準。

參考網站的做法Konbini調整理由
家樂福線上購物：結帳分成數個步驟，頂端顯示進度三步驟（購物車 → 填寫資料 → 完成），資料在同一頁要填的欄位不多，拆成多頁只會多按幾次「下一步」；步驟條只用來告訴使用者還剩幾步。
Instacart：結帳頁左側填資料、右側固定訂單摘要左表單、右側 sticky 摘要 360px送出按鈕放在摘要裡，金額與按鈕永遠在一起；與 /cart 的摘要同一個元件。
雜貨電商常見：配送時段選擇時段畫出位置、標為後端未支援ui-guidelines 列為雜貨電商特有需求，先保留位置。
全聯 PXGo!：手機結帳底部固定送出按鈕手機底部固定條：合計＋送出訂單表單很長，送出按鈕不能只在最底下；摘要裡的按鈕在手機隱藏，避免出現兩個。

Layout

為什麼這樣排

做法說明
不用 AuthCard表單頁規範的 480px 單欄卡片是為登入、註冊設計的；結帳要同時看到訂單內容，改成兩欄。輸入框 48px、送出按鈕 52px、錯誤處理照表單頁規範。
依主題分成幾張卡片收件人、配送方式、地址、時段、付款、備註各一張，掃一眼就知道還缺哪一塊；錯誤 modal 的順序與卡片順序一致。
帶入會員資料，但可以改寄給別人時要能改姓名與電話；不提供「同會員資料」勾選框，直接預填就好。
未登入requiresAuth 導到登入頁；登入後要回到 /checkout，需要前端補 redirect（見 cart.html）。

Notes

下一步

  • Email 驗證上線後，未驗證的帳號不能登入，自然也到不了結帳頁；結帳頁本身不用另外處理。
  • 送出成功回傳的只有 orderId，完成頁要顯示金額與地址，見 order-complete.html 的取捨。
  • 手機格式要不要檢查，與註冊頁的手機欄一起決定。
