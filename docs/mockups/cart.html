Ready · 現有的程式就做得到

  • 抽屜與側欄的唯讀清單 — 只讀 items 的名稱、圖片、數量，不呼叫任何修改方法。
  • 內容與數量 — useCartStore（Pinia＋localStorage）已有 items / quantity / subtotal / deliveryFee / total 與 add / updateQuantity / remove。
  • 免運進度 — 門檻與運費是前端常數 FREE_DELIVERY_THRESHOLD（與後端 Pricing 同為 NT$500、NT$60），差額直接算。
  • 每項上限 99 — MAX_ITEM_QUANTITY，與後端 OrderItem.MaxQuantity 一致。
  • 抽屜 — el-drawer（direction="rtl" size="420px"），手機改 size="100%"；焦點鎖定與 Esc 關閉是現成的。

Blocked · 後端沒有的功能

  • 庫存與缺貨提示 — 沒有庫存欄位，購物車無法提示「只剩 3 件」或「已售完」，ui-guidelines 的「庫存與購物車不同步時的提示」要等庫存上線。
  • 價格變動提示 — 購物車存的是加入當下的單價；後端改價後，要到送出訂單才會以新價格計算。要在購物車就提示，需要「依 id 批次查商品」的 API。
  • 跨裝置同步 — 購物車只在這台瀏覽器（CLAUDE.md §5 刻意的決定），草稿不畫「登入後合併購物車」。

Decision

抽屜 vs 固定側欄

A 右側抽屜B 固定側欄
列表密度不佔寬度，格線維持 4 欄佔 300px，格線剩 3 欄（一頁 20 件要 7 列）
看得到內容的時機點了 header 的購物車才看得到逛列表時一直看得到買了哪些
出現在哪些頁全站任何頁（header 的入口共用）只適合列表與搜尋；首頁、詳情頁仍要另一個入口
實作量一個全域元件＋開關狀態每個列表頁版型都要改成兩欄，平板以下還是要退回抽屜
適合的使用方式逛完再一起看邊逛邊對照清單（雜貨的大量採買）
共同規則兩種都只列名稱與數量，不能改數量、不顯示金額；唯一的按鈕是「查看購物車」。

兩種做法都改為唯讀後，差別只剩「要點開才看得到」或「一直看得到」。改數量、移除、金額與結帳都集中在 /cart，規則只有一處。

Reference

與參考網站的區塊對照

只記錄版型結構與資訊密度的觀察，不沿用任何網站的配色、圖示、文案與素材；細節實作前以實際網站為準。

參考網站的做法Konbini調整理由
Instacart：購物車從右側滑出，可直接改數量與結帳右側只列內容，按鈕改為「查看購物車」右側不放任何修改操作與金額；所有修改集中在 /cart，避免在兩個地方改同一份資料、看到兩個不同位置的合計。
雜貨電商常見：顯示距離免運還差多少免運進度條＋差額門檻 NT$500 不高，提示差額能直接帶動多買一兩項。
家樂福線上購物：完整購物車頁左清單、右摘要/cart 左清單、右側 sticky 摘要保留完整頁給手機與想仔細核對的人；桌機摘要 sticky，清單長也看得到結帳按鈕。
全聯 PXGo!：手機底部常駐購物車與結帳入口手機底部固定條：合計＋結帳ui-guidelines RWD 表的規定；列表頁的固定條導到 /cart，購物車頁的固定條直接結帳。

Layout

為什麼這樣排

做法說明
保留 /cart 完整頁它是唯一能修改購物車的地方：手機的底部固定條、桌機抽屜或側欄的「查看購物車」都連到這裡。
抽屜與側欄只看不改改數量、移除、金額、結帳都只在 /cart；右側只回答「買了哪些、各幾件」。數量減到 0 時跳 ElMessageBox 確認移除，這也只在 /cart 發生。
金額旁註明「以送出時為準」購物車的單價是加入當下的價格，下單時後端重新計價（CLAUDE.md §5）；先講清楚，結帳時金額變了才不會像是錯誤。
未登入按「前往結帳」/checkout 有 requiresAuth，會導到登入頁；登入後要回到結帳，需要前端補 redirect 參數（login.html 下一步已記錄）。購物車在 localStorage，登入過程不會遺失。
