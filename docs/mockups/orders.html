查看購物車

Ready · 現有的 API 就做得到

  • 列表與分頁 — GET /api/orders?page= 回 PagedResult<OrderDto>，每筆含 items / subtotal / deliveryFee / total / contactName / contactPhone / deliveryAddress / memo / createdAt，新的在前。
  • 商品縮圖 — OrderItemDto.imageUrl 已有。
  • 再買一次 — 用訂單上的 productId / productName / imageUrl 加入購物車；單價要用目前售價，最保險的做法是加入後由購物車照常顯示「以送出時為準」。
  • 日期格式 — 現在用 toLocaleString()，各瀏覽器顯示不同；建議與 formatMoney 一樣在 shared/ 加 formatDateTime，固定 YYYY/MM/DD HH:mm。

Blocked · 後端沒有的功能

  • 訂單狀態（處理中、已出貨、已完成、已取消）— 訂單沒有狀態欄位，狀態分頁與卡片上的標籤都接不到資料。狀態轉換是 §6 列出的「實質領域規則」之一。
  • 訂單明細頁 — 沒有 GET /api/orders/{id}；列表已經帶完整品項，明細頁的價值在狀態歷程與單筆分享連結。
  • 再買一次的下架判斷 — 要知道哪些商品還在賣，需要「依 id 批次查商品」的 API；沒有的話只能加入後在結帳時由後端擋下。
  • 期間篩選、搜尋訂單 — API 只有分頁。

Reference

與參考網站的區塊對照

只記錄版型結構與資訊密度的觀察，不沿用任何網站的配色、圖示、文案與素材；細節實作前以實際網站為準。

參考網站的做法Konbini調整理由
家樂福線上購物：訂單依狀態分頁籤狀態分頁（標為後端未支援）先畫位置；沒有狀態欄位前只顯示「全部」，分頁籤整列不出現。
Instacart：過去的訂單可以一鍵再買再買一次ui-guidelines「重複購買動線」；雜貨回購率高，這是訂單列表最有用的按鈕。
雜貨電商常見：每筆訂單一張卡片，品項多時收合卡片＋超過 3 項收合一筆可能有 30 項，全展開會把下一筆推到很遠；收合用 el-collapse-transition。

Layout

為什麼這樣排

做法說明
卡片，不用 el-table每筆訂單有多個品項，表格只能放摘要；卡片桌機與手機共用，不用像後台表格那樣另做窄螢幕版。
右側放地址、金額與按鈕左邊掃品項、右邊看金額；平板以下改成上下排，按鈕並排。
保留「再買一次」商品卡不放加入按鈕，加入購物車原則上只在商品說明頁；「再買一次」是唯一的例外，因為品項與數量已經在訂單上決定好，回購不必逐一點進說明頁。
寬度 1000px與 login.html 的窄版頁面同寬；訂單不需要 1180px，太寬時品項與金額離太遠。
