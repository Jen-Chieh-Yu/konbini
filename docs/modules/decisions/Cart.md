# Cart 業務決策紀錄

> 業務規則的決定與理由。現況規則見 [Cart.md](../Cart.md)，格式見 [模組總覽「業務決策紀錄」](../README.md#4-業務決策紀錄)。

## DD-CRT-001：購物車與現價、庫存的校正（2026-11-20，使用者決定；CLAUDE.md §6「購物車價格與現價不同步」）

- **背景**：購物車存的是加入當下的品名、單價與數量。商品改價、售完或被刪除後，結帳頁顯示的金額和實際成立的訂單不同，
  數量也可能超過庫存，要到送出訂單才由 400／409 擋下。之後權限管理的後台會加改價與下架，這個落差會變成常態。
- **決定**：
  - 用商品列表的 `ids` 篩選（`GET /api/products?ids=1&ids=2&pageSize=100`）取現價與庫存，不做試算端點；
    前端自己重算預覽金額（技術上的理由見 CLAUDE.md §5「購物車放前端」）。`ids` 不另設上限，一頁最多 100 筆。
  - 進購物車頁、進結帳頁時各校正一次；送出前不再另外查。結帳送出被拒、錯誤裡有 `items` 時再校正一次。
  - 價格不同：自動改成現價，提示「{品名}：價格從 NT$ {舊} 改為 NT$ {新}」。名稱、圖片不同：直接更新，不提示。
  - 數量超過庫存（庫存大於 0）：自動降到庫存數，提示「{品名}：庫存只剩 N 件，已調整為 N 件」，和加入購物車時的調整一致。
    購物車頁「＋」的上限改成庫存與 99 取小的。
  - 售完、查不到（已刪除；之後的下架也是）：保留那一列並標示「已售完」「已下架」，不算進金額；
    購物車裡有這種列時，「前往結帳」「送出訂單」停用，要先移除。查不到一律顯示「已下架」。
  - 連不到伺服器：購物車維持原樣，提示「暫時無法確認最新的價格與庫存，送出訂單時會再確認。」，不擋結帳。
  - 庫存只放在記憶體，不存進 localStorage。localStorage 的格式不變、不加版本號；載入時丟掉格式不對的列。
  - 結帳的 400、409 只要錯誤裡有 `items`，都顯示「回購物車調整」連結（原本只有 409 有「回購物車調整數量」）。
  - 取代 DD-ORD-002「結帳收到 409 時……不自動修改購物車」。
- **放棄的東西**：
  - 運費規則前後端各一份，預覽金額由前端計算；之後有折扣、優惠券時要重新評估試算端點。
  - 價格與數量是自動改的，使用者只能從提示得知，不能選擇保留原價（原價本來就不能成立）。
  - 售完的列要使用者自己移除才能結帳，比自動移除多一步；換來的是之後補貨時，使用者知道購物車裡原本有這項商品。
  - 校正和送出之間仍有時間差，這段時間被改價或買走時，一樣由下單的 400／409 擋下。
- **未做**：
  - 結帳 400「下列商品不存在」仍列商品 Id；權限管理的下架會改成 409「已停售」並列品名，到時一併處理。
  - header 的件數不校正；購物車沒有 50 項的上限，校正一次最多查 100 項。
  - 購物車頁、結帳頁整頁遷移到 UI 規範（CLAUDE.md §6「前端 feature 頁面遷移到 UI 規範」）。
- **驗證**：
  - 用 API 查 `ids`：存在、不存在、已軟刪除的 Id 混在一起，只回存在的；和 `type` 同時給時兩個條件都符合；值不是整數時回 400。
  - 用資料庫改價、改庫存、軟刪除後，在購物車頁與結帳頁看提示、標示、金額與停用的按鈕。
